A container packs the app with everything it needs to run, so it behaves the same on your laptop and in AWS. The [Lesson 2 app](https://github.com/aws-seneca/aws-101-workshop) already has a `Dockerfile`.

## Amazon ECS words

- **Image**: the packaged app. Stored in a registry such as Amazon ECR.
- **Task definition**: the blueprint, in JSON. Which image, how much CPU and memory, ports, environment, logging, and the IAM role.
- **Task**: one running copy of a task definition.
- **Service**: keeps a set number of tasks running and replaces any that stop. Can sit behind a load balancer.
- **Cluster**: the group your tasks and services run in.

## Fargate or EC2

- **AWS Fargate**: serverless compute for containers. You say how much CPU and memory each task needs; AWS runs it. No instances to patch or size.
- **EC2 capacity**: tasks run on EC2 instances you manage. More control, sometimes cheaper at steady high load.

Start with Fargate. See [Containers on ECS](/docs/architecture/7-containers).
