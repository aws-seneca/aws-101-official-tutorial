Amazon EC2 Auto Scaling manages a group of instances for you.

- **Minimum, desired and maximum**: the group keeps the desired number running, and never goes outside min and max.
- **Health checks**: an instance that stops, or fails the load balancer's health check, is replaced automatically.
- **Launch template**: the recipe for a new instance. AMI, instance type, security group and user data that installs and starts the app. Nobody logs in to set it up.
- **Scaling policy**: changes the desired count. A *target tracking* policy works like a thermostat: pick a metric and a target, such as average CPU at 50 percent, and the group adds or removes instances to stay near it.

## When to use it

Whenever more than one copy of an app runs on EC2. Even with a fixed size (min = max = 2), it replaces instances that die. Pair it with a [load balancer](/docs/concepts/load-balancing). See [Horizontal scaling](/docs/architecture/3-scaling/horizontal).
