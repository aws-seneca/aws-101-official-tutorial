When a site is only files, with no server-side code, you do not need a server. Put the files in S3 and put CloudFront in front.

This study guide is a static site: `npm run build` turns it into plain HTML files. It happens to be hosted on GitHub Pages, but S3 and CloudFront is the AWS way to do the same.

## When to use it

Portfolios, documentation, marketing pages, and front ends that call an API (see [Serverless](/docs/architecture/9-serverless)).

## Trade-offs

| | |
|---|---|
| Cost | Very low: pay for storage and data transfer |
| Complexity | Low: no servers, nothing to patch |
| Scaling | CloudFront handles traffic spikes for you |

No server-side code: anything dynamic (forms, logins, a database) needs an API somewhere else.
