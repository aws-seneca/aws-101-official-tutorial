This is Part 1 of [Lesson 2](/docs/app-to-rds/1-app-on-ec2).

## When to use it

A demo, a prototype, a personal project. Anything where losing the data is fine.

## Trade-offs

| | |
|---|---|
| Cost | Lowest: one small instance |
| Complexity | Lowest: one thing to launch and look at |
| Scaling | Only by making the instance bigger |

## What breaks

- **The data dies with the instance.** Terminate it, or lose its disk, and every sign-up is gone.
- **It cannot scale out.** A second instance would have its own `signups.json`, so the two would disagree.
- **Concurrent writes can clash.** Two sign-ups at the same moment can overwrite each other.

[2. Database tier](/docs/architecture/2-database-tier) fixes the first two by moving the data off the server.
