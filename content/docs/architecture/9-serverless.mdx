Serverless means you never size, patch or keep running a server. You upload code and data; AWS runs them when requests arrive and bills per request.

## How the sign-up app would look

- **The page**: static files in S3, served by CloudFront. See [Static site](/docs/architecture/6-static-site).
- **The API**: API Gateway turns `POST /signups` and `GET /signups` into calls to Lambda functions.
- **The code**: small Lambda functions, one per operation.
- **The data**: a DynamoDB table in on-demand mode. See [NoSQL (DynamoDB)](/docs/concepts/databases/nosql).

## When to use it

- Spiky or low traffic: a club app busy on event night and idle otherwise.
- Small APIs and glue between services.
- Pairs well with [Event-driven](/docs/architecture/8-event-driven) designs.

## When it is the wrong choice

- Long-running work (Lambda has a time limit per call), or steady heavy traffic where a server is cheaper.
- An existing app built around a server and a relational database. Moving it means rewriting it.

## Trade-offs

| | |
|---|---|
| Cost | Pay per request; close to nothing when idle |
| Complexity | A different way of writing apps: functions, events, NoSQL data modelling |
| Scaling | Automatic, per request |
