The classic layout for a web app. Each tier has one job, and each can only be reached from the tier in front of it.

1. **Presentation**: what the user sees. The browser, plus a load balancer (or CloudFront) as the only public entry point.
2. **Application**: the code that does the work. Instances or containers in private subnets with no public addresses.
3. **Data**: the database, in private subnets, reachable only from the application tier.

The security groups chain: the load balancer allows 443 from anywhere; the app allows its port only from the load balancer's security group; the database allows 5432 only from the app's security group.

## When to use it

Most web apps with a database. It is the shape behind [High availability](/docs/architecture/4-high-availability); this page is about the layers and the network rules.

## Trade-offs

| | |
|---|---|
| Cost | Private subnets need a NAT gateway for the app to reach the internet (updates, APIs), which bills by the hour |
| Complexity | More subnets, route tables and security groups |
| Scaling | Each tier scales on its own |
